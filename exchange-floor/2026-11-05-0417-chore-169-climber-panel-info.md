- **Decisions and why:**
  - The URL changes with `history.pushState`/`replaceState`, which Next.js keeps in sync with `useSearchParams`, and the panel loads its data through the action. Rendering the panel from `searchParams` on the server would re-render the whole `/desk` page (its `getDeskDay` and busyness) on every open and close. This way the table, its Filter list text and the scroll position are untouched (checked in a browser).
  - Close goes `history.back()` when the panel added the entry, otherwise `replaceState`, so Back never reopens a panel that ✕ closed.
  - Can-check-in uses `deskNextStep(climber) === null` (the same rules as `checkInClimber`); the fixes are the waiver (`waiverStatus !== "valid"`) and a pass (`badgeFor` is `NO_PASS`). Start waiver calls the existing desk waiver step `signWaiver` (the stopgap the scan popup and climber page use), so it records the waiver at once.
  - The panel is not a "desk dialog" (`desk-dialogs.ts`), so a QR scan still pops up over it.
  - Links go to `/desk/customers/<id>` (the #168 rename), not `/desk/climbers/<id>`.
  - Left out because no existing read returns them (the developer said not to add queries): Prior visit, the Visits tab, date joined, emergency contact, Undo (no undo action exists). Belay stays "Not recorded"; the photo stays a placeholder.
- **Gotchas:**
