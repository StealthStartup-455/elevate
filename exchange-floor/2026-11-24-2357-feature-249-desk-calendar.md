- **Decisions and why:**
  - `StaffShift` links to its class, event and set change by `(id, gymId)`, like `staffId`, so a shift can't point at another gym's row. `GymEvent` and `SetChange` got `@@unique([id, gymId])` for it.
  - The part of a multi-day item on its first or last day is cut off at the timeline's edge instead of stretching the timeline to midnight.
  - `/desk/events` now lands on Calendar (it was Hours), since Calendar is the first tab.
  - The day is in the address (`?day=`), so Back from a climber's account returns to it. Past and future months both work.
  - Cells count only what is still on; canceled items show in the day's list.
  - Day buttons use screen-reader text, not `aria-label`: axe's `label-content-name-mismatch` fails the latter.
- **Gotchas:** The e2e tests rely on the seed: the original five classes stay first and unchanged, days 1, 4 and 6 get nothing new, no second footwork or youth class lands in the next 14 days, and no new event starts before the film night (day 5) or runs through today. Past days show the regular hours as set now, because older regular hours aren't kept (special days are). Time zone data 2026e keeps Vancouver on one offset all year from November 2026, so clock-change tests use Toronto. A local database seeded before the calendar existed has no hours, classes or events. `npm run build` can stop once with a Next.js security notice.
