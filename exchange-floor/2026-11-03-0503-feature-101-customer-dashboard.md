- **Decisions and why:**
  - The typical-week numbers stay the labelled sample week (the developer's call); real numbers are still #39. Hours use the real clock (they have to be right); the live count still follows the mock scenario's fixed clock.
  - When the gym is closed and nobody is checked in, the card hides the level and bar; the "~N climbers here" line always shows (the release check reads it, and CI runs at any hour).
  - Banner: at most three events, canceled ones after the active ones, so a canceled event never crowds out one that is still on.
  - Class sign-up locks the `GymClass` row (`SELECT … FOR UPDATE`) before counting, so the last place goes to one climber. Any signed-in climber may sign up: no waiver or membership check, no payment, no waitlist (the developer chose free + capacity + cancel).
  - Staff forms take times on the gym's clock (`datetime-local`, `time` fields) and turn them into moments with `Gym.timeZone`. A closing time of 00:00 means midnight (1440). Any staff role can edit the calendar.
  - Events, set changes and classes are created and canceled, not edited: fix a typo by cancelling and adding again.
  - `/me/events` stays out of the climber menu (#65): everything is on the dashboard.
- **Gotchas:**
  - `prisma migrate dev --create-only` run twice applies the first migration and then writes an empty second one. If you need to add SQL (like the RLS lines) to a new migration, check `prisma/migrations` before re-running.
  - After pulling: `npx prisma migrate deploy`, `npx prisma generate`, then **restart `next dev`**. The running dev server keeps the old Prisma client, and every calendar query fails with "Cannot read properties of undefined (reading 'findMany')".
  - Re-running `npm run db:seed` gives every climber a new id, so a demo login cookie from before the seed drops you back to the login page.
  - With `DEV_AUTH_BYPASS="true"` in `.env`, the release check's "logged out visitors go to log in" step fails under `next dev` (known, see the 2026-10-30 #58 entry). It passes against the production build.
  - In the in-app browser pane, a hidden pane pauses animation frames, so streamed sections stay on their "Loading…" fallback. Not an app bug.
  - On `/desk/events`, scope e2e lookups to `<main>`: while the page streams in, a second copy of the hours form briefly exists.
  - `prisma/seed.ts` is also changed by open PR #160; this branch's edits are a few lines away from its hunks (an import, `resetCalendar` after the waiver template, `seedCalendar` before `seedLogins`), so it should merge cleanly.
